# Market Structure

A private research portal covering **CME, CBOE, ICE, HOOD, NDAQ, TW, and prediction markets**, migrated from the supplied portal and database. The original company workbenches, historical series, research views, consensus/scenario controls, chart tools, and prediction-market tools use external private storage. Original files remain intact outside Git.

Repository code contains reviewed presentation modules, shared calculations, loaders, documentation, and synthetic tests. Data-bearing literals, embedded research, source observations, original page content, styles, and source fingerprints remain in private storage. No verified refresh connection or public deployment is configured.

## Launch the migrated portal

Use **Node.js 24**. For the prepared Windows package, follow [the local-computer guide](docs/local-computer.md) and double-click `Start-Market-Structure.cmd`; no npm installation, Python, WSL, or Docker is needed for the viewer. Native Windows execution remains unverified in this Linux workspace.

Linux pins the SQLite descriptor through `/proc`; Windows uses a hash-verified private temporary copy and the native Node SQLite reader. The following commands are for the existing Linux development workspace. Install the two pinned development parsers used by code-porting and review checks:

```sh
cd /workspace/Market-Structure
npm ci --ignore-scripts --no-audit --no-fund --cache /workspace/.npm-market-structure-cache
PORT=3001 MARKET_STRUCTURE_DATA_DIR=/workspace/market-structure-private/runtime npm start
```

The last command uses the private runtime prepared in this cloud workspace. If the existing preview process is already running, open it instead of starting a second process. Open `http://127.0.0.1:3001` from that machine or through a private SSH tunnel. The cloud onboarding interface does not expose loopback previews. On another machine, substitute its external runtime and writable npm cache directories after following the import instructions below. The default port without `PORT` is 3000. Stop with Ctrl+C. Do not expose a port or preview publicly.

Without `MARKET_STRUCTURE_DATA_DIR`, `npm start` shows the separately maintained **synthetic monthly demonstration**. It does not include the private legacy workbenches. An explicitly configured invalid private runtime fails instead of substituting demonstration values.

The migrated portal shows observation dates and stale/missing-data warnings. Partial, forecast, blocked, and incomplete observations are excluded from derived comparisons where applicable. Unknown source units and provisional records without verified cutoffs remain flagged. “Reload” rereads the private release; it does not fetch market data.

## Import a private release

The full migration uses a standalone, checkpointed SQLite database plus a reviewed presentation pack. Both inputs and the runtime directory must be outside every Git checkout; preserve the original HTML, ZIP, reports, and extracted source database separately.

```sh
npm run data:import-legacy -- \
  --database /absolute/private/sources/database.sqlite \
  --presentation /absolute/private/presentation \
  --data-dir /absolute/private/runtime

MARKET_STRUCTURE_DATA_DIR=/absolute/private/runtime npm start
```

This generic command uses port 3000. The importer validates SQLite integrity, source-component hashes, every typed observation's source pointer/value, dates, units, and duplicate records. It copies inputs into a new immutable release, verifies presentation/code fingerprints, preserves older releases, and atomically activates `legacy.json`. Browser reload picks up an accepted release without a server restart. Daily, monthly, quarterly, partial-period, and source-specific histories retain their original definitions.

The presentation pack is generated by static parsing and must match reviewed code. It is **not an arbitrary HTML upload facility**. See [source migration and porting](docs/source-migration.md) before importing a changed portal. Raw source files and unrestricted filesystem paths are never exposed by the HTTP server; authorized portal users can access the private research content loaded into the application.

For an independent normalized monthly dataset, the optional `data:validate` and `data:import` commands remain available. They use `dataset.json` and the [monthly data contract](docs/data-contract.md). They are not required for, or replacements for, the full SQLite migration.

## Verify

```sh
npm run check
npm run test:browser
npm run test:legacy-browser -- --url http://127.0.0.1:3001
```

Core checks require Node 24, Python 3.12+, Git, and `npm ci`. Browser checks require Playwright and Chromium; the legacy check runs against an already started private portal. Its expectations are read from that runtime, never copied into repository fixtures. An optional `--report /absolute/private/new-browser-review` saves private evidence outside Git.

For browser tooling on another machine:

```sh
python3 -m venv /absolute/external/portal-test-tools
/absolute/external/portal-test-tools/bin/python -m pip install -r requirements-dev.txt
/absolute/external/portal-test-tools/bin/python -m playwright install chromium
PATH=/absolute/external/portal-test-tools/bin:$PATH npm run test:browser
```

Chromium may also need Linux system dependencies. An installed `chromium` is used when available; `CHROMIUM_PATH` selects another executable. See [review and verification](docs/review.md) for completed checks and remaining operational work.

## Maintain the application

| Location | Purpose |
| --- | --- |
| `src/legacy-store.js`, `src/legacy-runtime.js` | Read-only database validation, private releases, presentation integrity |
| `src/legacy-analytics.js` | Reviewed calendar comparisons and safe CSV values |
| `public/legacy/`, `public/legacy-*` | Reviewed presentation code, private bootstrap, integration hooks |
| `src/domain.js`, `public/app.js` | Optional normalized monthly demonstration |
| `scripts/` | Static source porting, private imports, validation, privacy gate |
| `tests/`, `examples/` | Synthetic fixtures/checks and a runtime-only private QA harness |

Review code diffs and the private source mapping together when regenerating legacy modules. Private packs are tied to exact code fingerprints; editing modules requires a matching reviewed pack. Keep reports, commentary, real observations, fingerprints, credentials, screenshots, and browser downloads outside every Git checkout. Automated privacy checks supplement manual review.

[Private hosting and refresh operations](docs/private-hosting.md) describes authentication, TLS, persistent storage, backups, licensed source adapters, and scheduling. A future refresh must reconcile both the database and snapshot-specific content in the private presentation pack. No Git push or public publication is part of this migration.

For a concrete deployment package, follow the [private hosting handoff](docs/hosting-handoff.md): an unprivileged system service, a required persistent data mount, and access through the user's restricted SSH key. The package requires an authorized host and a separate durable backup destination; it does not turn this development sandbox into a hosted website.
